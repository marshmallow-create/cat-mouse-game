# 全ユーザーのランキングと自己ベスト

2026-10-12の画面フィードバックに対応。

- 初期選択はレチェ。ページを再読み込みするとレチェに戻る。ラテを選んで遊ぶこともできる。
- 「みんなのランキング」は全ユーザーのプレイ記録の上位10件。ユーザー名・スコア・遊んだ日時を表示する。同じユーザーの複数の記録も対象。同点なら新しい日時、さらに同じ日時なら新しい記録番号を優先する。
- 「自己ベストランキング」は廃止。「利用者アカウント」に本人の最高スコアだけを表示する。全体の上位10件に入らなくても表示できる。未プレイなら「まだ記録がありません」と表示する。
- 保存成功・ログイン・ランキングの更新で、自己ベストもデータベースから読み直す。ログアウトすると自己ベストを隠す。取得失敗時は確認できなかった旨を表示する。

## データの流れ

ブラウザが `GET /api/rankings` を呼ぶと、サーバーがログイン状態を確認し、PostgreSQLから `results`（全体の上位10件）と `personalBest`（本人の最高記録、未プレイはnull）を返す。

ランキングのSQLは `JOIN` を使う。これは2つの表を共通の番号で結び付ける命令。`game_results.user_id` と `game_users.id` を結び付け、スコアにユーザー名を添える。所有者不明の旧記録はユーザー名と結び付けられないため、全体ランキングの対象外となる。記録自体は保持する。

自己ベストのSQLは、サーバーがセッションから確認した本人の番号で絞り込み、最高スコアの1件を取得する。パスワードやセッション情報はランキングに含めない。保存の所有者確認・CSRF確認・二重保存防止は引き続き行う。既存の表・索引を使うため、DBのセットアップをやり直す必要はない。

## 自分で試す

1. `npm.cmd start` で起動し、`http://localhost:3000` を開いてログインする。
2. レチェが選ばれ、START画面にもレチェが表示されることを確認する。
3. 2つのアカウントで遊び、それぞれのユーザー名が同じランキングに表示されることを確認する（上位10件に入った記録が対象）。
4. アカウント欄の自己ベストが本人の最高スコアであることを確認する。低いスコアで遊んでも最高スコアは下がらない。
5. 再読み込み後も自己ベストが残り、ログアウトすると隠れることを確認する。

業務システムでも、売上表と社員表をJOINして全社の成績を表示し、本人の成績だけを別に集計するような場面に使える。
