# 記録に使用した猫を表示する

自己ベストには `自己ベスト：45匹（使用した猫：レチェ）` のように表示し、みんなのランキングには「使用した猫」の列を追加します。

## 保存の流れ

1. ゲーム開始時の猫を、終了時のスコアと一緒に未送信の控えに入れます。
2. ブラウザがAPI（サーバーの受付窓口）へ `catType: "leche"` または `"latte"` を送ります。
3. サーバーが値を確認し、プレイ結果の `cat_type` 列に保存します。
4. ランキングと本人の最高記録を取得するときに、その列も返して猫名を表示します。

過去の記録と旧形式の未送信控えには猫の情報がありません。推測せず、DBではNULL（情報なし）、画面では「不明」にします。同じスコアなら従来どおり新しい記録を優先し、その記録で使用した猫を表示します。

## 起動と確認例

ローカルDBは `node scripts/database.js auth-setup` で猫の列も準備できます。クラウドDBには `database/cat-info.sql` と同じ追加を適用してから、新しいサーバーを起動します。既存の記録を削除する処理はありません。

`npm.cmd start` で起動し、次を試してください。

- レチェで遊び、保存後にランキングの猫が「レチェ」になることを確認する。
- ラテに変えて遊び、その記録の猫が「ラテ」になることを確認する。
- 自己ベストを更新できなかった場合、自己ベストの猫が最高記録の猫のままであることを確認する。
- 再読み込み後も猫名が残ること、以前の記録は「不明」と表示されることを確認する。

通信が失敗した場合の控え、保存の再試行、バックアップと復元にも猫の情報を含めます。古いバックアップも復元でき、その記録の猫は不明になります。

業務システムでも、売上や作業時間だけでなく「使用した設備」「担当部署」などを記録と一緒に保存することで、後から条件を正しく確認できます。現在選択中の値ではなく、記録当時の値を保持するのが今回のポイントです。
