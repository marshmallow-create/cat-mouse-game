# 学習と実装の計画

## 目的と合意した方針

- 今の猫とネズミのブラウザゲームを教材に、複数の人が利用し、記録を共有データベースに蓄積する仕組みを学ぶ。
- 将来の会社用システムに生かせる、データ設計・API・ログイン・権限・運用の理解を目指す。
- 画面は現在のHTML・CSS・JavaScriptを生かす。サーバーはNode.js、データベースはPostgreSQLを使う。
- ブラウザ → サーバー → データベースの流れを、一段階ずつ実装する。
- 初回の保存対象は自分の過去のプレイ記録。その後、利用者ごとの記録へ広げる。
- 学習のため、実装だけでなく初心者向けの解説を必ず添える。
- この文書は計画の記録であり、各段階は実装・確認できた時点で完了に更新する。

## 段階1：サーバーでゲームを開く

状態：完了（2026-10-07）

- Node.jsでゲームのHTML・CSS・JavaScript・画像を配信する。
- ファイルを直接開く方法から、localhostのアドレスで開く方法へ移る。
- 学ぶこと：ブラウザとサーバーの違い、HTTPのリクエストとレスポンス、サーバーの起動と停止。
- 到達点：localhostで画像が表示され、START・カウントダウン・操作・ゲーム終了・再挑戦が動く。
- 実装：`server.js` の標準HTTPサーバー、`package.json` の起動コマンド、`Markdown/README.md` の学習ガイド。
- 起動：プロジェクトのフォルダーで `node server.js`、ブラウザで `http://localhost:3000`。停止はCtrl + C。
- 確認：7つの配信URLの内容と種類、日本語画像名、存在しないURL、サーバー側ファイルの非配信、停止・再起動、別フォルダーからの起動。
- ブラウザ確認：Edgeで画像・CSS、3秒カウントダウン、WASD・矢印キー、捕獲・加点、30秒の実時間での終了、5秒ごとのネズミ追加、再挑戦。JavaScript例外と通信エラーは0件。
- 学習用の確認例：`Markdown/README.md` で要求ログ・404・停止と再起動を試せる。

## 段階2：データベースを作る

状態：完了（2026-10-08）

- PostgreSQLを用意し、プレイ結果を保存する表を作る。
- 最初は記録番号・スコア・遊んだ日時を保存する。
- 学ぶこと：表・行・列、主キー、SQLでの追加・読み出し・並べ替え。
- 到達点：練習用の記録をSQLで追加し、スコア順で取り出せる。
- 環境：Windows x64用PostgreSQL 18.6を `.local/postgres/` に配置。接続先 `127.0.0.1:5433`、データベース `latte_game`、管理用利用者 `latte_admin`。
- 表：`game_results`。`id` は自動採番の主キー、`score` は必須かつ0以上、`played_at` は必須かつ省略時に現在日時。
- 実装：`database/schema.sql`、`database/practice.sql`、`scripts/database.js`、npmの `db:*` コマンド。データ・実行ファイル・接続パスワードは `.gitignore` で除外。
- 学習ガイド：`Markdown/DATABASE_STAGE2.md`。起動・停止、SQLの手入力、保存の確認、用語と会社用システムへのつながりを解説。
- 確認：追加・読み出し・スコア順と同点時の日時順、0点と既定日時、負のスコア・未入力・主キー重複の拒否、練習SQLの繰り返し、停止・再起動後の永続化、setup再実行時の記録保持。
- 検証用の行は削除済み。練習SQLはROLLBACKで取り消すため、ゲーム用の表は空の状態で引き渡し。
- PostgreSQLは検証後に停止。自分で試すときは `node scripts/database.js start`、続けて `node scripts/database.js practice` または `shell` を実行する。
- 段階3では、ブラウザからの保存・取得APIと、管理用アカウントから分けたゲーム用DB接続権限を整理する。

## 段階3：ゲームとデータベースを接続する

- サーバーに結果保存とランキング取得のAPIを作る。
- ゲーム終了時に保存し、過去のランキングを表示する。
- 最初の表示案：上位10件、同点は新しい日時を優先。実装時に必要なら調整する。

## 解説の付け方

各段階では、次の順で説明する。

1. 今回できるようになることと、その目的。
2. 画面・サーバー・データベースのどこを変更するか。
3. 新しい用語の意味と、今回の機能での具体例。
4. 実装後の変更点、起動方法、動作の確認方法。
5. 利用者が自分で試せる小さな確認例と、会社用システムへのつながり。

- 一度に多くの段階を実装せず、現在の段階の到達点を確認してから進める。
- 解説は日本語で、短いまとまりに分ける。用語だけで説明せず、具体例を添える。
- 動作やデータ保存に関わる確認は行い、確認できた内容と未確認の内容を区別する。
- 実装が完了したら、この文書の状態・到達点・次の段階を更新する。
