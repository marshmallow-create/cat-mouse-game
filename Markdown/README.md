# ラテのネズミさがし：段階1の学習ガイド

この段階では、Node.jsのサーバーからゲームのファイルを受け取り、ブラウザで遊べるようにします。ロードマップと進捗は `LEARNING_PLAN.md` に記録しています。

## 起動と停止

PowerShellでプロジェクトのフォルダーに移動して起動します。

```powershell
cd C:\marshmallow\codex_projects\cat-mouse-game
node server.js
```

`ゲームを開く: http://localhost:3000` と表示されたら、ブラウザでそのアドレスを開きます。起動したターミナルは開いたままにしてください。STARTを押すと3秒のカウントダウン後にゲームが始まります。

停止するときは、ターミナルで **Ctrl + C** を押します。再開するときは、もう一度 `node server.js` を実行します。

Node.js 22以上が必要です。`node --version` で確認できます。この段階では外部ライブラリがないため、`npm install` は不要です。`package.json` に起動方法を登録してあるので、`npm start` でも同じサーバーを起動できます。

## 今回増えたファイル

| ファイル | 役割 |
|---|---|
| `server.js` | Node.jsで動き、ブラウザからの要求にファイルを返す |
| `package.json` | プロジェクト名や起動コマンドを記録する |
| `Markdown/README.md` | 起動方法、仕組み、学習用の確認例を説明する |

`index.html`、`style.css`、`script.js`、`images/` はブラウザへ配信するファイルです。特に `script.js` はゲームを動かすブラウザ側のJavaScript、`server.js` は要求を受け付けるサーバー側のJavaScriptです。

## ブラウザから画面が表示されるまで

1. アドレスに `http://localhost:3000` を入力します。
2. ブラウザがサーバーへ「`/` の内容をください」と要求します。
3. サーバーは `index.html` を読み、ブラウザへ返します。
4. HTMLを読んだブラウザが、CSS・JavaScript・画像も要求します。
5. サーバーがそれぞれのファイルを返し、画面が表示されます。

この要求を **リクエスト**、返される内容を **レスポンス** と呼びます。HTTPは、このやり取りに使う決まりです。

- `localhost`：このPC自身を指す名前。
- `3000`：サーバーが要求を受ける窓口の番号。これをポートと呼びます。
- `/style.css`：サーバーに要求する場所。サーバーは対応表から返すファイルを決めます。
- `Content-Type`：返すものがHTML・CSS・画像などのどれなのか、ブラウザに伝える情報。
- `200`：正常に内容を返せたことを示す番号。
- `404`：要求されたページが見つからなかったことを示す番号。

`file:///.../index.html` で開くと、ブラウザは直接PCのファイルを読みます。`http://localhost:3000` で開くと、Node.jsのサーバーを通して受け取ります。将来はこの窓口に「記録を保存して」「ランキングを取得して」というAPIを追加します。

## server.jsの読み方

上から順に、次のまとまりとして読むと理解しやすくなります。

1. **標準機能を読み込む**：HTTPサーバー、ファイルの読み出し、ファイルの場所を扱う機能を使います。
2. **配信するファイルを登録する**：URLとファイル名、Content-Typeの対応表を用意します。
3. **要求を受けたときの処理を書く**：URLを調べ、ファイルを読み、レスポンスを返します。`await` はファイルの読み込みが終わるまで、その処理の続きを待つための書き方です。
4. **待ち受けを始める**：`server.listen` でポート3000を開きます。

サーバーは対応表に登録したゲーム用ファイルを配信します。`server.js` や、将来のデータベース接続設定はブラウザに配信しません。日本語の画像名も扱えるよう、URLの文字を復元してから対応表を確認しています。

## 自分で試す確認例

### 画面を再読み込みする

ブラウザを再読み込みし、ターミナルを見ます。

```text
GET / → 200
GET /style.css → 200
GET /script.js → 200
```

画像の要求も表示されます。`GET` は「内容を取得したい」という要求です。日本語の画像名はURL上で `%` を含む文字列に変換されるため、ログでは見た目が変わることがあります。

F12でブラウザの開発者ツールを開き、「ネットワーク（Network）」を選んで再読み込みすると、同じ要求をブラウザ側からも見られます。

### 存在しないページを開く

`http://localhost:3000/not-found` を開いてみます。「ページが見つかりません。」が表示され、ターミナルには `404` が出ます。ファイルがない場合もサーバーはレスポンスを返しています。

### サーバーを停止する

Ctrl + Cで停止し、ブラウザを再読み込みします。サーバーが停止しているため、新しく画面を取得できなくなります。再起動後に再読み込みすると表示されます。

停止前から開いているゲームは、ブラウザがすでに受け取ったJavaScriptで動いているため、再読み込みするまでは遊べることがあります。

## 困ったとき

- **ポート3000が使用中**：同じサーバーを別のターミナルで起動していないか確認します。別のポートで試す場合は、PowerShellで次のように指定できます。

  ```powershell
  $env:PORT = "3001"
  node server.js
  ```

  表示された `http://localhost:3001` を開きます。この環境変数は現在のターミナルに残るので、3000へ戻す場合は `$env:PORT = "3000"` と指定します。

- **npm startがPowerShellで実行できない**：`node server.js` で起動できます。
- **追加した画像が表示されない**：`server.js` の対応表に、その画像のURLとファイル名を登録します。
- **サーバーのコードを変更した**：Ctrl + Cで停止してから再起動します。HTML・CSS・ゲーム用JavaScript・画像の変更はブラウザの再読み込みで反映されます。

## 会社用システムへのつながり

会社用システムでも、ブラウザが要求し、サーバーが処理して返す流れを使います。今はファイルを返していますが、段階3ではサーバーがデータベースへ記録を保存したり、記録を読み出したりする処理を加えます。

次の段階2ではPostgreSQLを用意し、表とSQLを学びます。この段階1にはデータベースとランキング保存はまだ含まれていません。
