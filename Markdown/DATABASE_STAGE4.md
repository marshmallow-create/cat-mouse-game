# 段階4：利用者登録・ログインと、自分の記録

利用者ごとにスコアを保存し、自分の上位10件を表示するようにしました。例えば「alice」で遊んだ結果は「bob」のランキングには出ません。持ち主はサーバーがログイン情報から決めます。

## 起動と遊び方

このPCの段階4用データベースは準備済みです。PowerShellで次を実行します。

```powershell
cd C:\marshmallow\codex_projects\cat-mouse-game
node scripts/database.js start
node scripts/server.js
```

ブラウザで **http://localhost:3000** を開きます。起動済みのサーバーはCtrl + Cで止めて再起動し、ブラウザも再読み込みしてください。

ログイン前はログイン画面を表示し、猫選択・ゲーム画面・自己ベストランキングはログイン後に表示します。猫選択欄で、レチェの鰹節・ラテの苺が5秒ごとに出現し、取ると5秒間スピードが2倍になることを案内します。ログアウトするとゲーム画面とランキングは再び非表示になります。

1. 利用者名とパスワードを入力して「新規登録して始める」を押します。
2. 利用者名は半角英数字・_で3〜32文字、パスワードは12〜128文字です。利用者名の大文字と小文字は同じ名前として扱います。
3. 「○○でログイン中です」と表示されたらSTARTを押します。矢印キーまたはWASDで遊びます。
4. 終了すると自分の記録として保存され、自分のランキングが更新されます。
5. 次回は同じ名前・パスワードで「ログイン」を押します。Cookieが有効なら再読み込み後もログイン中です。

停止はサーバーのターミナルでCtrl + C、その後 `node scripts/database.js stop` です。利用者と記録は残ります。

別のPCや新しいチェックアウトでは、Node.js 22以上を用意し、最初に次を一度実行します。既存の記録を削除せず段階2・3・4の準備を行います。

```powershell
npm.cmd ci
node scripts/database.js auth-setup
```

`auth-setup` は再実行できます。段階4の準備には `api-setup` ではなく `auth-setup` を使います。

## データの流れと外部キー

ブラウザが登録・ログインの情報を送ると、サーバーがパスワードを照合し、ログイン状態をDBへ保存します。ゲーム終了時には、サーバーがそのログイン状態から利用者番号を調べ、スコアと一緒に保存します。

新しい表は `game_users`（利用者）と `game_sessions`（ログイン状態）です。`game_results` に `user_id`（利用者番号）を追加しました。

例：番号3の利用者が12匹捕まえると、結果の表に「スコア12・利用者番号3」を保存します。**外部キー**は、その番号が実在する利用者を指すことをDBが確認するルールです。

段階3までの結果は所有者を特定できないので、利用者番号が空のまま残しています。新しいランキングには表示しません。旧形式の未送信控えも残しますが、新しいアカウントへ自動送信しません。移行が必要なら、持ち主を確認して別途行います。

## 認証と権限

**認証**は「誰が操作しているか」の確認です。Node.js標準のscryptでパスワードをハッシュ化して照合します。生のパスワードはDBやlocalStorageに保存しません。利用者ごとにランダムなソルトを作り、scryptの設定はN=131072・r=8・p=1です。

**権限**は「その人に何を許すか」の確認です。サーバーはログイン中の利用者番号でランキングを絞り込みます。保存要求にはプレイ番号とスコアだけを受け付け、持ち主はサーバーが決めます。他人のプレイ番号を送っても、その結果を返したり上書きしたりしません。編集・削除のAPIは設けていません。

会社用システムでも、ログインで本人を確認してから「自分の申請だけ閲覧できる」「管理者だけ承認できる」といった権限を確認します。

## Cookieとセッション

**Cookie**はブラウザが保存し、同じサーバーへの要求に付ける小さな情報です。今回は推測しにくいランダムなセッション番号をCookieに入れ、DBにはそのハッシュと利用者番号・有効期限を保存します。

期限はログインから12時間です。ログアウトするとDBのセッションとCookieを無効にします。同じブラウザで新しくログインすると古いセッションも無効になります。セッションはDBにあるので、サーバーやDBを再起動しても期限内なら使えます。

CookieにHttpOnly（JavaScriptから読み出せない）・SameSite=Strict（別サイトからの要求には送らない）を指定しています。POSTではOrigin（操作元のサイト）を確認し、ログイン後の操作ではCSRFトークンも確認します。CSRFトークンは、外部サイトから勝手に操作されることを防ぐための確認値です。登録・ログインはJSONと同じOriginを必須にし、15分間に30回までに制限します。

現在はこのPCからだけ接続できるlocalhost用HTTPサーバーです。公開する段階5ではHTTPS、CookieのSecure属性、運用向け認証設定を整えます。パスワード再設定・メール確認は今回の範囲に含めていません。

## 保存失敗と利用者切替

未送信の結果をlocalStorageの **利用者番号ごとのキー** に控えます。Aの保存が失敗してからBへ切り替えても、Bのログイン中にAの結果を再送しません。Aでログインし直すとAの控えを再送できます。

プレイ中・送信中は画面の利用者切替を無効にします。別タブでログインしてCookieが変わった場合も、サーバーがCSRFトークンと画面の利用者番号を確認し、保存とランキング取得を拒否します。画面を再読み込みして状態を確認し、未送信記録は元の利用者で保存してください。ログイン後の利用者アカウント欄とログアウトボタンはページの一番下に表示します。

控えは同じブラウザの同じアドレスに保存されます。サイトデータを削除すると未送信の控えも消えます。保存済みの記録はDBに残ります。

## 自分で試す確認例

1. `alice` と `bob` を別々に登録し、それぞれで1回遊びます。ランキングが分かれることを確認します。
2. ログアウトし、もう一方でログインします。最初の利用者の記録が表示されないことを確認します。
3. 間違ったパスワードでログインし、エラーになることを確認します。
4. ブラウザを再読み込みし、ログインと記録が残ることを確認します。
5. 保存失敗を試すなら、ゲーム開始後に別のPowerShellで `node scripts/database.js stop` を実行します。終了後に失敗表示が出たら `node scripts/database.js start` で復旧し、「保存を再試行する」を押します。DB停止中はログイン操作も失敗します。

## 変更と検証

- `database/stage4.sql`：利用者・セッションの表、外部キーと索引。
- `scripts/auth.js`：登録・パスワード照合・Cookie・セッション・CSRF・試行制限。
- `scripts/api.js`、`scripts/game-store.js`：ログイン確認と利用者ごとの保存・取得。
- `scripts/database.js`：`auth-setup` コマンド。
- `index.html`、`style.css`、`scripts/script.js`：ログイン画面、利用者別の控えとランキング。
- `tests/stage3.test.js`：保存・ランキングの結合テストをログイン必須へ更新。
- `tests/stage4-browser.test.js`：Edgeで実際のゲーム・登録・切替・再送を検証。

```powershell
npm.cmd test
```

ローカルDBの停止・再起動も含むので、遊んでいないときに実行してください。テストで作成したアカウントと結果だけを削除します。Edgeがない環境ではブラウザテストをスキップします。

参考：[Node.jsのscrypt](https://nodejs.org/docs/latest-v22.x/api/crypto.html#cryptoscryptpassword-salt-keylen-options-callback)、[OWASPのパスワード保存](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)、[OWASPのセッション管理](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)。

## 実装時の確認結果（2026-10-11）

- API結合テストとEdgeのブラウザテストがそれぞれ成功。2人分の記録の分離、他人の番号による保存拒否、同時再送の重複防止を確認。
- 誤パスワード、入力制約、利用者名の重複と大文字小文字、認証試行制限、CSRF・Origin、ログアウト・期限切れを確認。
- DB停止・復旧と、HTTPサーバー・DB再起動後の記録・ログイン状態の保持を確認。
- Edgeで実時間30秒、移動、ネズミ追加、登録・切替・ランキング、未送信控えの再読み込み後の保持、元利用者での再送を確認。
- 共有Cookieが別利用者へ切り替わった状態でも誤保存・別人のランキング表示を拒否し、元利用者で再ログインすると再送できることを確認。
- ブラウザのJavaScript例外は0件。保存要求の遮断とCookie切替によるエラーは検証のため意図的に発生させたもの。
- 検証用のアカウント・結果だけを削除し、検証用HTTPサーバーとEdgeは終了。既存の記録は保持。
